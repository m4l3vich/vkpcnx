Borealis Developer Guide

Borealis is a C++17, gamepad-first UI toolkit: XML view trees, flexbox layout (Yoga), vector rendering (nanovg), one code base for desktop, Switch, PS4, PS Vita, Android, iOS and tvOS. This guide covers the app skeleton, the XML/C++ authoring model, and a reference for every view — extracted automatically from library/borealis.

Namespacebrls — include <borealis.hpp> LayoutYoga flexbox — axis, grow, alignItems, justifyContent behave like CSS Input modelOne focused view at a time; D-pad / stick moves focus, A = click, B = back. Mouse and touch map onto the same actions. Resourcesresources/ next to the binary (or bundled with libromfs): xml/, i18n/, img/, font/

Quickstart: a barebones app

  1. Clone the template (this repository). It already contains library/borealis as a submodule, a demo/ app, and a CMake setup for every target. Run git submodule update --init --recursive after cloning.
  2. Build for desktop to iterate quickly: 
    cmake -B build -DPLATFORM_DESKTOP=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/borealis_demo          # resources/ is copied next to the binary
    Other targets: -DPLATFORM_SWITCH=ON, -DPLATFORM_PS4=ON, -DPLATFORM_PSV=ON, -DPLATFORM_ANDROID=ON, -DPLATFORM_IOS=ON, -DPLATFORM_TVOS=ON. On macOS add -DBUNDLE_MACOS_APP=ON for a .app.
  3. Replace demo/src/main.cpp with the minimum: 
    #include <borealis.hpp>

class MainActivity : public brls::Activity
{
  public:
    // Inflate the activity from resources/xml/activity/main.xml
    CONTENT_FROM_XML_RES("activity/main.xml");
};

int main(int argc, char* argv[])
{
    brls::Logger::setLogLevel(brls::LogLevel::LOG_INFO);

    if (!brls::Application::init())
        return EXIT_FAILURE;

    brls::Application::createWindow("My app");   // window title (i18n keys work too)
    brls::Application::setGlobalQuit(true);       // START button quits

    brls::Application::pushActivity(new MainActivity());

    while (brls::Application::mainLoop());
    return EXIT_SUCCESS;
}
  4. Write the first screen in resources/xml/activity/main.xml: 
    <brls:AppletFrame iconInterpolation="linear">
    <brls:TabFrame title="My app" icon="@res/img/icon.png">

        <brls:Tab label="Home">
            <brls:Box axis="column" padding="30" width="auto" height="auto">
                <brls:Label text="Hello from Borealis" fontSize="24" marginBottom="20" />
                <brls:Button id="hello" style="primary" text="Press A" />
            </brls:Box>
        </brls:Tab>

        <brls:Separator />

        <brls:Tab label="Settings">
            <brls:View xml="@res/xml/tabs/settings.xml" />
        </brls:Tab>

    </brls:TabFrame>
</brls:AppletFrame>
  5. Run it. You get the title bar, sidebar, hint bar and focus handling for free. Press A on the button — nothing happens yet, which is the next section.

Debugging layout

Every View has a wireframe flag (setWireframeEnabled(bool) / isWireframeEnabled(), or the wireframe="true" XML attribute) that draws its frame in blue and its margin/padding boxes in green — the fastest way to see why something isn't sized or positioned the way you expect. It's per-view, so recurse over a Box's children to outline a whole subtree.

// Outline a single view (frame in blue, margins/padding in green):
view->setWireframeEnabled(true);

// Or via XML, on any view:
// <brls:Box wireframe="true" ...>

// Outline an entire subtree from C++:
void enableWireframeRecursive(brls::View* view)
{
    view->setWireframeEnabled(true);
    if (auto* box = dynamic_cast<brls::Box*>(view))
        for (brls::View* child : box->getChildren())
            enableWireframeRecursive(child);
}

// e.g. in Activity::onContentAvailable(), on the activity's content view.

Separately, Application::enableDebuggingView(true) toggles the FPS/frametime overlay — useful for performance, not layout.

Building UIs with XML

Every built-in view has a brls: tag; any class you register with Application::registerXMLView("Name", factory) becomes a <Name /> tag. Attributes are applied in document order through typed setters, so an unknown attribute or an illegal enum value is a fatal error at inflate time — not a silent no-op.

Composition

  • <brls:View xml="@res/xml/tabs/settings.xml" /> inlines another XML file.
  • <brls:Tab label="…"> / <brls:Separator /> are only valid inside <brls:TabFrame>.
  • Give a view an id to reach it from C++ (getView("id") or BRLS_BIND) and to target it with focusUp/Down/Left/Right.
  • Composite views forward attributes to children (e.g. a cell's title goes to its Label) — these show up as "forwarded" in the reference.

Activities

An Activity is one full screen (usually an AppletFrame). Application::pushActivity(new X()) animates it in; B or Application::popActivity() returns. Views can also be pushed alone with the same call. Dialog::open() and Dropdown use the same stack.

Threads and timing

UI must be touched from the main thread. Use brls::sync([]{ … }) from workers, brls::delay(ms, cb) for timers, and brls::Animatable / Application::getAnimationDelta() for animated properties (alpha, positions, etc.).

Layout & common attributes

Every view carries the Yoga box model. Children of a Box are laid out on its axis; grow distributes leftover space; alignItems / justifyContent position them. The Layout tab of the demo is the fastest way to see each value.

Themes & styles

Colours live in brls::Theme (two variants: ThemeVariant::LIGHT / DARK, selected with getPlatform()->setThemeVariant()), metrics in brls::Style. Both are name → value maps you can extend with Theme::addColor / Style::addMetric and reference from XML as @theme/ and @style/.

Built-in token names all start with brls/ (e.g. brls/accent, brls/background, brls/sidebar/active_item, brls/button/primary_enabled_background); the full list is in library/lib/core/theme.cpp and style.cpp. Add your own with Style::addMetric("app/my_token", value) / Theme::addColor(...) and reference them the same way.

Icons

Borealis has two unrelated ways to show an icon — pick based on whether you have artwork or just want a glyph.

Bitmap icons (your own artwork)

An ordinary brls::Image (or AppletFrame::setIcon(path), which just sets a bound Image's source and toggles its visibility). Use for app/title icons, avatars, anything that isn't a simple monochrome glyph.

appletFrame->setIcon("@res/icon/vkplay.png");

Glyph icons (font-based)

There is no dedicated icon widget. FONT_MATERIAL_ICONS and FONT_SWITCH_ICONS are registered as nanovg fallback fonts on top of the regular font at startup (see desktop_font.cpp). Any codepoint missing from the regular font — a Private-Use-Area codepoint that only exists in one of the icon fonts — renders from that fallback automatically. So a glyph icon is just a brls::Label whose text is that codepoint; no icon-specific API.

icon->setText("\uE0E0"); // BUTTON_A glyph, see table below

Material Icons ligature names aren't enumerated anywhere in this codebase (the font is loaded but no code references specific glyphs), so there's no generated list for it here.
